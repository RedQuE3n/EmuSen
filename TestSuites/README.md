# TestSuites/

Third-party, MIT-licensed test ROMs vendored directly into this repo -
**not** the same thing as the gitignored `TestRoms/` at the project root,
which is for copyrighted commercial ROMs used for local debugging and must
never be committed. Everything under here is safe to commit because it's
open-source and permissively licensed; each vendored package keeps its own
`LICENSE` file (see below) rather than being folded into this project's own
top-level `LICENSE` (GPL-3.0) - MIT code embedded in a GPL project is
standard practice and does not relicense the vendored code itself.

## `snes-tests/` ([gilyon/snes-tests](https://github.com/gilyon/snes-tests), MIT)

Comprehensive 65C816 (`cputest/`) and SPC-700 (`spctest/`) opcode test ROMs
- real, bootable `.sfc` files that exercise (per their own README) "all
65C816 opcodes except STP and WAI" and "all SPC-700 opcodes except SLEEP and
STOP," each in every supported addressing mode, with edge cases and flag
results checked. Vendored as delivered (the project's own release-zip
contents: prebuilt ROMs, the assembly source, the autogenerated
`tests-*.txt`/`tests.txt` descriptions of every individual test, and the
Python/Makefile build scripts to regenerate them) - see `snes-tests/README.md`
and the per-subdirectory READMEs for the full detail on what's tested and
what isn't (timing/cycle counts, hardware interrupts, and memory-mapped
registers are explicitly out of scope for `cputest`; dummy reads,
S-SMP-mapped registers, and the DSP are out of scope for `spctest`).

Two `.gitignore` files that shipped inside the original release zip
(`cputest/.gitignore`, `spctest/.gitignore`) were removed before committing -
they exist in the upstream *development* repo to keep autogenerated files
out of *their* git history between rebuilds, which doesn't apply to a
vendored release snapshot; keeping them would have silently dropped the
`tests-*.txt`/`tests-*.inc`/`tests_table.inc`/`spc_tests*.asm` files (the
"autogenerated tests.txt files" and "autogenerated assembly files" the
upstream README explicitly lists as part of what a release zip contains)
from this repo's own tracked files.

**Complementary to, not a replacement for, `EmuSen.Validation`'s existing
TomHarte/ProcessorTests-based single-step validation** (see
`EmuSen_Debugging_Tools_Reference_v5.md` §3.16) - that harness single-steps
one instruction at a time against JSON ground-truth vectors and checks
register/memory state byte-for-byte; these are real, bootable ROMs meant to
run end-to-end inside the emulator itself (`EmuSen.HeadlessDebug`'s
`--commands` scripting, §3.15, is the natural way to drive one - boot, run
frames, read back a pass/fail indicator) and catch a different class of bug:
anything that only shows up running as real 65816/SPC700 machine code
through the full CPU/APU pipeline, not just via the single-step adapter
`EmuSen.Validation` drives directly. Not wired into either harness yet -
vendored here so that integration is a follow-up, not blocked on
re-sourcing the ROMs.
