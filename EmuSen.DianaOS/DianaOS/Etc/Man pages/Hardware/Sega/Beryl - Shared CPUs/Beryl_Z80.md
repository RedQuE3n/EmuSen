# Beryl_Z80 — the Z80's record

*Started 2026-10-04, at stage 0.* `beryl-z80`, the Zilog Z80 shared by Nephrite's sound CPU and, later, Endou's and
Jadeite's main CPU. Planned in `Nephrite_Plan.md` §8 and §6's stage 2; the common interface is `README.md` beside this
page. Registers as in `Nephrite_Native.md`.

## 1. Stage 0 (2026-10-04)

The bus trait, the registers and the step's signature (`NotBuilt` while `BUILT` is false), and the single-step harness
with its controls. No instruction is implemented.

## 2. The interface

- **`Bus`**: `fetch` (the M1 cycle's read, then the refresh with I and R on the address bus), `read`, `write`, `input`
  and `output` (the whole 16-bit port address, as the processor drives it), `idle` (T-states without a memory or I/O
  cycle), `int_line`, `nmi_edge` and `acknowledge` (the byte a device places on the bus during the interrupt
  acknowledge, mode 0's instruction or mode 2's vector). The bus adds WAIT's states: on the Genesis, the Z80's window
  onto the 68000's space costs both processors.
- **`Registers`**: the main and alternate pairs, IX, IY, SP, PC, I, R, WZ (MEMPTR), Q (whether the last instruction
  changed the flags, which SCF and CCF read), P (whether the last instruction was LD A,I or LD A,R, whose P/V an
  accepted interrupt changes), IFF1, IFF2, IM, and EI's one-instruction delay.

## 3. The oracle

### 3.1 The single-step harness

`src/singlestep.rs`, over SingleStepTests' `z80/v1` (1,604 files × 1,000 cases, every opcode with its prefixes; its
README says it was generated from a translation of another emulator's core, and its `generation/` folder is not read),
found through `EMUSEN_BERYL_CORPUS`.

**The bus** answers memory from the case's list and port reads from the case's `ports` in order, and records each call
as the T-states the suite samples, expanded by the patterns the suite's data shows (statements about the file format,
not the hardware):

| Call | T-states (address, data, pins `rwmi`) |
|---|---|
| fetch | (pc, –, `----`), (pc, –, `r-m-`), (refresh, opcode, `----`), (refresh, –, `----`) |
| read | (a, –, `----`), (a, –, `r-m-`), (a, value, `----`) |
| write | (a, –, `----`), (a, value, `-wm-`), (a, –, `----`) |
| input | (p, –, `----`), (p, –, `----`), (p, –, `r--i`), (p, value, `----`) |
| output | (p, –, `----`), (p, –, `----`), (p, value, `-w-i`), (p, –, `----`) |
| idle | (any, –, `----`) per T-state |

The suite samples between T-states and pulses MREQ with RD or WR for one T-state (its README's "simplified memory
access" option); both are the generator's conventions, which the harness reproduces rather than judges. **An internal
T-state's address is not compared:** the suite's README says it records the last address driven "for convenience",
the address pins being disconnected; the Genesis's bus does not observe it. Each case is graded on the registers, the
memory, and the T-state list with the I/O transactions.

**The controls (measured 2026-10-04).**

- *Positive:* a replay that reads each case's T-states back into the bus calls that make them and performs them,
  ending in the case's registers: **1,604,000 of 1,604,000** pass, in 3.8 s on four threads.
- *Negative:* the carry flipped in the final F, and the last T-state dropped, over the first 200 cases of every eighth
  file: **0 of 40,200** pass for each.
- *The unbuilt processor* fails the inline case.

### 3.2 The hardware-grounded check

ZEXDOC and ZEXALL (`agn453/ZEXALL` @`8f71d41`), whose CRCs were taken on real Z80s, run at stage 2 in the crate under a
small CP/M shim (BDOS functions 2 and 9). They are the one Z80 oracle not generated by an emulator (`Nephrite_Plan.md`
§9, Q3).
